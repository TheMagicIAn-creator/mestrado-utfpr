## Autoencoder - modelo de normalidade

Aqui, o Autoencoder (AE) foi treinado para aprender o comportamento "normal" dos sinais CA do inversor, usando o dataset Paderborn (que contém dados de um inversor saudável). O objetivo é que ele reconstrua bem os dados normais e mal os dados anômalos. O erro de reconstrução é a métrica que usamos para identificar anomalias.

*   **Limiar p99 (2.9103):** Este é o valor de erro de reconstrução acima do qual consideramos um dado como anômalo. Ele foi definido como o percentil 99 dos erros de reconstrução dos dados de validação *saudáveis*. Ou seja, 99% dos dados normais têm um erro de reconstrução abaixo desse valor.
*   **Média baseline (0.3214) e Desvio baseline (0.5017):** Representam a média e o desvio padrão dos erros de reconstrução para os dados *saudáveis*. O limiar p99 está significativamente acima da média, indicando que o modelo é sensível a desvios. A comparação com a linha de base (μ+3σ = 0.30 + 3*0.38 = 1.44, usando os valores da injeção de falhas) mostra que o p99 é mais conservador e robusto.
*   **Falsos positivos validação (4.35%):** É a porcentagem de dados *saudáveis* que foram erroneamente classificados como anômalos durante a validação do modelo. Um valor baixo como este é desejável, pois indica que o modelo não está gerando muitos alertas desnecessários.
*   **Épocas treinadas (84):** O número de ciclos completos de treinamento que o modelo passou pelo dataset até atingir uma boa performance e convergir.

A leitura rápida que fiz é que o detector está calibrado por erro de reconstrução. Quanto maior a distância entre o erro de uma falha e o limiar, mais clara e detectável é a anomalia.

*   **Margem (1.13x, 1.04x, 10.99x):** A razão entre o "Erro na SMD" e o "Limiar". Indica o quão acima do limiar o erro de reconstrução da falha se encontra na SMD. Uma margem maior significa uma detecção mais robusta e clara. A falha de sensor CA tem uma margem enorme, o que é excelente.

A leitura rápida que fiz é que a SMD é a menor severidade em que o Autoencoder cruza o limiar. Isso nos diz o quão cedo podemos detectar cada tipo de falha.

## Validação formal

Esta seção avalia o desempenho do modelo de detecção de anomalias (o Autoencoder com o limiar) usando métricas de classificação padrão, comparando os dados com falha injetada (rotulados como anomalia) versus os dados saudáveis (rotulados como normais).

*   **Falha (Degradação Filtro LCL, Desbalanceamento de Fase, Falha de Sensor CA):** As falhas avaliadas.
*   **Severidade (1.0, 0.5, 0.3):** A severidade da falha utilizada para esta validação específica. Note que para o desbalanceamento e falha de sensor, usamos severidades menores que a SMD, o que é um teste mais rigoroso.
*   **AUC-ROC (0.935, 1.000, 1.000):** Área sob a Curva ROC (Receiver Operating Characteristic). É uma métrica que avalia a capacidade do modelo de distinguir entre classes (normal vs. anômalo). Um valor de 1.0 indica uma separação perfeita, enquanto 0.5 indica um desempenho aleatório. Nossos resultados são excelentes, especialmente para desbalanceamento e falha de sensor.
*   **F1 (0.632, 0.980, 0.980):** Média harmônica da Precisão e do Recall. É uma métrica de equilíbrio que penaliza modelos com desempenho muito bom em uma métrica e ruim em outra.
*   **Recall (0.480, 1.000, 1.000):** Também conhecido como Sensibilidade, mede a proporção de anomalias *reais* que foram corretamente identificadas pelo modelo. Um Recall de 1.0 significa que todas as anomalias foram detectadas.
*   **Precision (0.923, 0.962, 0.962):** Mede a proporção de detecções de anomalias do modelo que são *realmente* anomalias. Uma Precisão alta significa poucos falsos positivos.

A leitura rápida que fiz é que AUC próximo de 1 indica separação muito forte entre comportamento saudável e falha injetada. Isso mostra que o nosso modelo é muito eficaz em identificar as falhas que simulamos.

## RUL / Weibull

Esta seção se aprofunda na análise de confiabilidade, usando a distribuição de Weibull para estimar a Vida Útil Restante (RUL - Remaining Useful Life) e outras métricas de confiabilidade para as falhas.

*   **Falha (Degradação Filtro LCL):** A falha para a qual a análise Weibull foi realizada.
*   **NPR (210):** O Número de Prioridade de Risco da FMECA, reforçando a criticidade desta falha.
*   **beta (2.251):** O parâmetro de forma da distribuição de Weibull.
    *   Se beta < 1, a taxa de falha diminui com o tempo (falhas infantis).
    *   Se beta = 1, a taxa de falha é constante (falhas aleatórias, como na distribuição exponencial).
    *   Se beta > 1, a taxa de falha aumenta com o tempo (falhas por desgaste, envelhecimento). Nosso beta de 2.251 indica que a degradação do filtro LCL é uma falha por desgaste, o que é esperado para componentes eletrônicos.
*   **eta (46.0):** O parâmetro de escala da distribuição de Weibull, também conhecido como vida característica. É o tempo em que aproximadamente 63.2% dos componentes falharam. Neste caso, 46.0 unidades de tempo (horas, ciclos, etc., dependendo da unidade do nosso dataset) é a vida característica do filtro LCL sob as condições simuladas.
*   **MTTF (40.7):** Mean Time To Failure (Tempo Médio Até a Falha). É a vida útil média esperada do componente. Para a degradação do filtro LCL, esperamos que, em média, ele falhe após 40.7 unidades de tempo.
*   **B10 (20.0):** É o tempo em que 10% dos componentes falharam. É uma métrica útil para planejar a manutenção preventiva, pois indica um ponto onde uma pequena, mas significativa, parte da população de componentes já falhou.

A interpretação que fiz é que esses parâmetros nos permitem estimar a vida útil esperada do componente e planejar estratégias de manutenção preditiva com base na probabilidade de falha ao longo do tempo.

### **1. Autoencoder (AE) - Modelo de Normalidade**

O principal modelo de Machine Learning empregado aqui é um **Autoencoder (AE)**.

*   **O que é:** Um Autoencoder é uma rede neural artificial não supervisionada, projetada para aprender uma representação eficiente (codificação) dos dados de entrada. Ele consiste em duas partes principais: um **encoder**, que comprime os dados de entrada em uma representação de menor dimensão, e um **decoder**, que tenta reconstruir os dados originais a partir dessa representação comprimida.
*   **Como funciona para detecção de anomalias:** A ideia central é treinar o AE exclusivamente com dados de comportamento *saudável* (normal) do inversor. Durante o treinamento, o AE aprende a reconstruir com alta precisão os padrões normais. Quando dados *anômalos* (com falhas) são apresentados ao AE, ele terá dificuldade em reconstruí-los com a mesma fidelidade, pois nunca "viu" esses padrões antes. A diferença entre os dados de entrada e os dados reconstruídos é chamada de **erro de reconstrução**.
*   **Aplicação no projeto:** No nosso caso, o AE foi treinado com o dataset Paderborn (dados de inversor saudável). O erro de reconstrução é usado como uma métrica de anomalia: um erro de reconstrução elevado indica um desvio significativo do comportamento normal, sinalizando uma potencial falha. O **limiar p99** (percentil 99 do erro de reconstrução dos dados saudáveis) é o ponto de corte que define o que é considerado anômalo.

### **2. Injeção de Falhas Sintéticas e Validação Formal**

Essas etapas não utilizam redes/modelos de Machine Learning adicionais, mas sim **metodologias** para avaliar a performance do Autoencoder.

*   **Injeção de Falhas Sintéticas:** Esta é uma técnica para simular condições de falha em dados saudáveis. No nosso pipeline, aplicamos transformações nos dados de entrada (que representam o comportamento saudável) para mimetizar os efeitos de falhas específicas (como degradação do filtro LCL, desbalanceamento de fase e falha de sensor CA). O objetivo é gerar dados "com falha" controlados para testar a capacidade do AE de detectá-los. A **Severidade Mínima Detectável (SMD)** é a menor intensidade da falha injetada que o AE consegue consistentemente identificar como anomalia (cruzando o limiar).
*   **Validação Formal:** Após a injeção de falhas, os dados (saudáveis e com falha injetada) são passados pelo Autoencoder, e seus erros de reconstrução são analisados. Métricas como **AUC-ROC, F1-Score, Recall e Precision** são calculadas para quantificar a eficácia do AE em distinguir entre o comportamento normal e as falhas injetadas. Essas métricas nos dão uma visão robusta da capacidade de detecção do modelo.

### **3. Análise de Confiabilidade (Weibull)**

A análise de Weibull é um **modelo estatístico** utilizado para prever a confiabilidade e a vida útil de componentes.

*   **O que é:** A distribuição de Weibull é uma das ferramentas mais versáteis na análise de confiabilidade, pois pode modelar uma ampla variedade de comportamentos de taxa de falha (constante, crescente ou decrescente) ao longo do tempo. Ela é definida por dois parâmetros principais:
    *   **Beta (β):** O parâmetro de forma, que descreve como a taxa de falha muda com o tempo. Se β < 1, a taxa de falha diminui (falhas infantis). Se β = 1, a taxa de falha é constante (falhas aleatórias, como na distribuição exponencial). Se β > 1, a taxa de falha aumenta (falhas por desgaste).
    *   **Eta (η):** O parâmetro de escala, que representa a vida característica do componente (o tempo em que 63,2% dos componentes falharam).
*   **Aplicação no projeto:** No nosso contexto, a análise de Weibull é aplicada para estimar o **Tempo Médio Para Falha (MTTF)** e o **B10 Life** (o tempo em que 10% dos componentes falharam) para as falhas identificadas. Isso nos permite quantificar a confiabilidade dos componentes e estimar o **Remaining Useful Life (RUL)**, fornecendo informações cruciais para a manutenção preditiva.

Em resumo, o Autoencoder é o coração da detecção de anomalias baseada em ML, enquanto a injeção de falhas e a validação formal são as metodologias para testar e comprovar sua eficácia, e a análise de Weibull é a ferramenta estatística para traduzir essa detecção em métricas de confiabilidade e vida útil.

### **Engenharia de Características dos Sinais CA (features_ca)**

1.  **Coleta dos Sinais Brutos:**
    *   Começamos com os dados de sinais elétricos CA, que são as leituras de corrente e tensão nas fases do inversor. No nosso caso, o dataset Paderborn fornece esses dados em alta frequência de amostragem (10 kHz), o que é excelente para capturar detalhes.

2.  **Extração em Diferentes Domínios:**
    *   Para que o Autoencoder possa "entender" o comportamento do inversor, precisamos extrair características que capturem aspectos importantes desses sinais. Fazemos isso analisando os dados em diferentes perspectivas:
        *   **Domínio do Tempo:** Aqui, observamos como o sinal se comporta diretamente ao longo do tempo.
            *   **Exemplos de características:**
                *   **Valor RMS (Root Mean Square):** Indica a "potência efetiva" do sinal. Mudanças no RMS podem sinalizar problemas de carga ou geração.

                *   **Assimetria (Skewness):** Mede a assimetria da distribuição do sinal.
                *   **Curtose (Kurtosis):** Mede o "achatamento" da distribuição, indicando a presença de picos ou caudas pesadas.
                *   **Fator de Crista (Crest Factor):** Relação entre o valor de pico e o valor RMS, sensível a picos transitórios.

Isso nos permite ver quais frequências compõem o sinal e com que intensidade. Falhas em inversores frequentemente se manifestam como alterações nos harmônicos.
            *   **Exemplos de características:**
                *   **Amplitude de Harmônicos Específicos:** A 3ª, 5ª, 7ª harmônica, etc. Alterações aqui são cruciais para detectar problemas de distorção.
                *   **THD (Total Harmonic Distortion - Distorção Harmônica Total):** Uma métrica que quantifica o nível de distorção harmônica presente no sinal. Um aumento no THD é um forte indicador de degradação de componentes como filtros LCL ou problemas na comutação do inversor.
                *   **Potência em Bandas de Frequência:** A energia contida em faixas específicas do espectro.

3.  **Por que é Crucial para o Autoencoder:**
    *   O Autoencoder é treinado para aprender padrões. Se dermos a ele os sinais brutos, ele teria que aprender a extrair essas características por conta própria, o que é mais complexo e exige uma arquitetura muito maior.

    *   Após a extração, essas características são geralmente normalizadas (escaladas para um intervalo comum, como 0 a 1, ou padronizadas) para evitar que características com valores absolutos maiores dominem o processo de treinamento do Autoencoder.

        *   **Domínio Tempo-Frequência (Opcional, se necessário):** Para capturar eventos transitórios ou mudanças no espectro ao longo do tempo.
            *   **Coeficientes de Wavelet:** Podem decompor o sinal em diferentes escalas, revelando detalhes em diferentes frequências e momentos.

3.  **Normalização e Seleção de Características:**
    *   Após a extração, as características serão normalizadas (por exemplo, Z-score ou Min-Max Scaling) para garantir que todas tenham a mesma escala e não haja uma característica dominando o processo de aprendizado do Isolation Forest.
