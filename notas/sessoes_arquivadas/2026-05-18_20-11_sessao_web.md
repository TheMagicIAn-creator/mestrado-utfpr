## Limitações do Fluxo RAG para Enumeração Completa

Meu funcionamento é baseado em um fluxo específico para buscar conhecimento:

1.  Quando você faz uma pergunta, ela é transformada em um **vetor (embedding)**.
2.  Este vetor é usado para buscar os *trechos mais semanticamente relevantes* no **ChromaDB**, que é onde os 28 PDFs estão indexados.

O objetivo desse processo é fornecer respostas precisas e contextualizadas para *perguntas específicas*, e não para "despejar" todo o conteúdo da base de conhecimento ou listar todos os seus metadados. O sistema de busca vetorial é otimizado para **relevância**, não para **enumeração completa**.

### Sugestão de Próximos Passos Técnicos:

Você poderia implementar uma função no seu script `agente.py` ou `indexador.py` que faça uma consulta ao **ChromaDB** para listar todos os documentos e seus metadados (como título, autor, ano). Um pseudocódigo para isso seria:

```python
# Exemplo conceitual de como listar documentos do ChromaDB
import chromadb

def listar_todos_documentos_chromadb(caminho_db, nome_colecao):
    client = chromadb.PersistentClient(path=caminho_db)
    collection = client.get_or_create_collection(name=nome_colecao)
    
    # Recupera todos os documentos (ou um número limitado para evitar sobrecarga)
    # O método get() pode ser usado para recuperar documentos por ID ou com filtros
    # Para listar todos, pode ser necessário iterar ou ajustar o limite
    # Este é um exemplo simplificado, a implementação real pode variar
    
    # Uma forma de obter todos os metadados seria:
    results = collection.get(ids=collection.get()['ids'], include=['metadatas'])
    
    documentos_completos = []
    for i, metadata in enumerate(results['metadatas']):
        documentos_completos.append({
            'id': results['ids'][i],
            'titulo': metadata.get('titulo', 'N/A'),
            'autor': metadata.get('autor', 'N/A'),
            'ano': metadata.get('ano', 'N/A'),
            'fonte': metadata.get('source', 'N/A') # 'source' geralmente guarda o nome do arquivo
        })
    return documentos_completos
```
