Aqui está um script em Python interativo para rodar direto no terminal. Ele usa a biblioteca `sympy` para aceitar qualquer expressão matemática digitada no prompt, calculando tanto **integrais indefinidas** (primitivas) quanto **integrais definidas** (com limites).

### Código: Calculadora Interativa de Integrais (`calculadora_integral.py`)

```python
import sys
import sympy as sp


def menu():
    print("=" * 55)
    print("      CALCULADORA INTERATIVA DE INTEGRAIS (SymPy)     ")
    print("=" * 55)
    print("1 - Integral Indefinida (Simples / Primitiva)")
    print("2 - Integral Definida (com limites a e b)")
    print("0 - Sair")
    print("-" * 55)


def ler_expressao(var_sym):
    """Lê a expressão do usuário e converte para objeto do SymPy."""
    while True:
        raw_expr = input("\nDigite a função f(x) (ex: x**2 + 3*x, sin(x), exp(-x)): ").strip()
        try:
            # Transforma a string em expressão matemática reconhecida pelo SymPy
            expr = sp.sympify(raw_expr)
            return expr
        except Exception as e:
            print(f"❌ Erro ao interpretar a expressão: {e}")
            print("Dica: Use '*' para multiplicação (ex: 2*x) e '**' para potência (ex: x**2).")


def resolver_indefinida(x):
    expr = ler_expressao(x)
    print("\nCalculando...")
    resultado = sp.integrate(expr, x)
    
    print("\n" + "—" * 40)
    print(f"📥 Função original : f(x) = {expr}")
    print(f"📤 Integral∫f(x)dx : {resultado} + C")
    print("—" * 40)


def resolver_definida(x):
    expr = ler_expressao(x)
    
    try:
        lim_inf_str = input("Digite o limite INFERIOR (a): ").strip()
        lim_sup_str = input("Digite o limite SUPERIOR (b): ").strip()
        
        # Converte os limites (aceita frações como 1/2, pi como sp.pi, etc.)
        lim_inf = sp.sympify(lim_inf_str)
        lim_sup = sp.sympify(lim_sup_str)
        
        print("\nCalculando...")
        res_exato = sp.integrate(expr, (x, lim_inf, lim_sup))
        
        print("\n" + "—" * 40)
        print(f"📥 Função original : f(x) = {expr}")
        print(f"📍 Intervalo       : [{lim_inf}, {lim_sup}]")
        print(f"📤 Resultado exato : {res_exato}")
        
        # Se o resultado puder ser convertido para decimal
        try:
            res_num = float(res_exato.evalf())
            print(f"🔢 Valor decimal   : {res_num:.6f}")
        except Exception:
            pass
        print("—" * 40)

    except Exception as e:
        print(f"❌ Erro no cálculo dos limites: {e}")


def main():
    # Define a variável simbólica 'x'
    x = sp.Symbol('x')
    
    while True:
        menu()
        opcao = input("Escolha uma opção (0, 1 ou 2): ").strip()
        
        if opcao == '1':
            resolver_indefinida(x)
        elif opcao == '2':
            resolver_definida(x)
        elif opcao == '0':
            print("\nSaindo da calculadora. Até logo!")
            sys.exit(0)
        else:
            print("\n❌ Opção inválida! Tente novamente.")
        
        input("\nPressione ENTER para continuar...")


if __name__ == "__main__":
    main()
```

---

### Como usar no terminal
1. Salve o código em um arquivo, por exemplo `calculadora.py`.
2. Execute no terminal:
   ```bash
   python calculadora.py
   ```
3. O prompt vai pedir para você escolher a opção e digitar a função:
   * Multiplicação: use `*` (ex: `2*x`)
   * Potência: use `**` (ex: `x**3`)
   * Funções trigonométricas/exponenciais: `sin(x)`, `cos(x)`, `exp(x)`, `log(x)`
   * Limites especiais: aceita `pi` ou frações como `1/2` direto no prompt.

## Interação 16

**Você:** O que acha de integrar um MCP ou VSP em você? Seja honesto.

**Al IAdo PV:**

Seja pelo **MCP** (*Model Context Protocol*) ou por um **VSP** (*Vector Search Provider* / Banco Vetorial Dedicado), minha avaliação técnica e pragmática sobre integrar essas estruturas ao nosso ambiente atual é a seguinte:

---

### 1. Model Context Protocol (MCP)

O MCP (padronizado pela Anthropic) é um protocolo cliente-servidor para expor ferramentas, arquivos e contextos para LLMs de forma unificada.

#### 🟢 Onde ele agrega valor real:
* **Interoperabilidade de Frontends:** Se você quiser usar o Al IAdo PV em diferentes interfaces (ex.: Cursor IDE, VS Code, Claude Desktop, Obsidian local ou nossa interface Streamlit) consumindo **exatamente a mesma lógica de ferramentas** (rodar pipeline, consultar artefatos, ler vault), o MCP é imbatível. Você escreve o servidor de ferramentas uma única vez.
* **Isolamento de Execução:** Encapsula as operações do pipeline em scripts isolados via JSON-RPC/stdio, reduzindo o risco de acoplamento direto no código do agente principal (`agente.py`).

#### 🔴 As ressalvas para o nosso projeto:
* **Overhead de Infraestrutura sem ganho de acurácia:** Hoje, o `agente.py` já mapeia e executa os scripts do pipeline e consultas aos artefatos via *Function Calling* nativo da API. Se você só usa o agente por uma interface principal, migrar para MCP adiciona uma camada de abstração (protocolo de transporte, serialização) sem melhorar em nada a capacidade do modelo de detectar falhas ou interpretar gráficos.
* **Diagnóstico de Erro:** Quando um script local falha no pipeline (ex.: GPU sem memória no treino do Autoencoder), a captura de traceback via MCP pode ficar mais obscura do que a chamada direta em Python.

---

### 2. Vector Search Provider (VSP / Banco Vetorial Dedicado)

Refere-se a substituir ou expandir nossa busca híbrida local (BM25/FTS5 + Embeddings com RRF) por um provedor/banco vetorial dedicado (como Qdrant, Chroma local, Milvus ou Pinecone).

#### 🟢 Onde ele agrega valor real:
* **Escalabilidade Extrema:** Se a nossa base explodir de centenas para dezenas de milhares de artigos, teses e logs brutos de inversores, um VSP gerenciado com índice HNSW oferece buscas semânticas em milissegundos com baixo consumo de memória RAM principal.
* **Filtragem Complexa por Metadados:** Permite filtrar instantaneamente buscas por intervalo de datas, nível de evidência (E0 a E3), componente (IGBT, Contator) ou tipo de documento antes de aplicar o cálculo de similaridade.

#### 🔴 As ressalvas para o nosso projeto:
* **Perda de Precisão em Termos Exatos:** A busca puramente vetorial é péssima para termos exatos do nosso domínio (ex.: `SMD95`, `p99`, `NPR=315`, `SA43`, `FMECA`). Qualquer VSP adotado **teria que obrigatoriamente manter o motor léxico (BM25/FTS5)** em modo híbrido.
* **Complexidade Desnecessária:** Para o volume do mestrado (vault Obsidian + repositório de literatura e artefatos de resultados), nosso motor híbrido local roda rápido, em memória/disco local, sem exigir subir serviços em background (containers Docker do Qdrant/Milvus, por exemplo).

---

### Parecer do Coorientador e Recomendação

1. **MCP:** **Adote apenas se** você pretende usar o agente direto do seu editor de texto (ex.: Cursor/VS Code) para codificar o pipeline enquanto conversa comigo no mesmo painel. Se a interface Web/Streamlit atual atende, mantenha o *Function Calling* nativo.
2. **VSP:** **Não vale a pena no momento.** A arquitetura RAG híbrida atual (BM25 + vetores + reranking) atende perfeitamente ao volume de literatura e memória do projeto, sem o custo de manutenção de um banco de dados vetorial externo.

Se quiser testar o MCP para integrar o vault e os scripts diretamente no seu editor de código, posso te mostrar como estruturar o servidor Python em poucas linhas.

**Você:** me explique o que é esse smd e qual a relevância dele. ele aparece em quais literaturas?

**Al IAdo PV:**

O termo **SMD** possui dois significados no contexto da sua pesquisa, a depender do domínio em discussão: o hardware/confiabilidade do inversor (**eletrônica de potência**) ou a validação de algoritmos (**Machine Learning**).

---

### 1. Surface-Mount Device (Dispositivo Montado em Superfície) — Eletrônica e Confiabilidade

Na engenharia elétrica e eletrônica de potência, **SMD** refere-se à tecnologia de componentes montados e soldados diretamente sobre a superfície da placa de circuito impresso (PCB), sem a necessidade de perfurações (*through-hole*). No inversor fotovoltaico, isso inclui capacitores, resistores, optoacopladores, sensores e circuitos integrados de acionamento de gate (*gate drivers*).

#### Relevância para a Dissertação:
* **Mecanismos de Falha e Ciclagem Térmica**: Devido à operação contínua do inversor com variações térmicas diárias (ciclo de irradiância e carga), os componentes SMD e suas juntas de solda sofrem expansão e contração mecânica contínuas. A fadiga das juntas de solda (*solder joint cracking*) é uma das causas primárias de falhas intermitentes em placas eletrônicas.
* **Impacto na Assinatura Elétrica**: Degradações em componentes SMD do circuito de acionamento (*gate driver*) dos IGBTs alteram a dinâmica de comutação do semicondutor (tempos de *turn-on* e *turn-off*). Isso reflete diretamente na geração de **harmônicos de alta frequência** e **transientes de comutação**, afetando os sinais do lado CA monitorados pelo Autoencoder.

#### Literaturas onde aparece:
* **Cristaldi et al. (2017)** (*A Root Cause Analysis And A Risk Evaluation Of PV Balance Of System*): Na análise de causa-raiz e avaliação de risco de componentes de controle e acionamento do inversor.
* **Shuttleworth et al. (2015)** (*Reliability Prediction Of PV Inverters Based On MIL-HDBK-217*): Na modelagem estatística de taxas de falha ($\lambda$), onde componentes SMD possuem fatores de estresse térmico ($\pi_T$) e ambiental ($\pi_E$) específicos na predição de confiabilidade de hardware do inversor.
* **Stender et al. (2020)** (*Data Set Description Three Phase IGBT Two-Level Inverter*): Na especificação dos circuitos de amostragem e condicionamento de sinal da topologia de inversor trifásico utilizada para gerar o dataset.
* **Torres (2024)** / **Lafraia**: Na fundamentação de RCM e FMEA para subsistemas eletrônicos internos do inversor, onde a falha do componente SMD leva ao modo de falha funcional do bloco (ex.: perda de disparo do IGBT).

---

### 2. Server Machine Dataset (SMD) — Benchmark em Machine Learning

No contexto de **Machine Learning para Detecção de Anomalias em Séries Temporais**, **SMD** também é uma sigla consagrada para o *Server Machine Dataset*, um conjunto de dados benchmark público amplamente utilizado na literatura para avaliar algoritmos não supervisionados (como Autoencoders, Isolation Forest e LSTMs).

#### Relevância para a Dissertação:
* **Validação Cruzada de Modelos**: Artigos da literatura recente utilizam o dataset SMD como etapa prévia de validação de arquiteturas de Autoencoder para provar a capacidade do modelo em aprender padrões de normalidade e reconstrução antes de aplicar o modelo ao dataset fotovoltaico ou de inversores.

#### Literaturas onde aparece:
* **Ibrahim et al. (2022)**, **Francisti et al. (2025)** e **Ahirwar et al. (2025)**: Em revisões e proposições de arquiteturas de detecção de anomalias por reconstrução de sinal (*reconstruction loss*), onde o SMD é citado como padrão de comparação entre diferentes algoritmos da literatura.
